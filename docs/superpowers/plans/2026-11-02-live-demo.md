# Live Demo (webcam coaching, per-arm counting) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `formcoach demo --camera N` gives live coaching from the CV pipeline: skeleton on the live video, one rep counter per arm, elbow angles, an angle trace, a status pill, a coaching banner after every rep, an optional wearable gate/LED, and a per-arm session log.

**Architecture:** Turn `run_pipeline`'s closures into a stateful `Pipeline` class (`on_imu`/`set_gate`/`on_frame`/`finish`) that holds one or two `_Track`s (one per arm for curl/press/raise, one for squat and for replay). `run_pipeline` becomes a thin wrapper and replay output stays byte-identical, pinned by a golden test written first. A new frame-driven `app/live.py` loop feeds camera/video frames through the real MediaPipe detector (injectable for tests) into `Pipeline`, draws a `app/hud.py` frame, and optionally follows a wearable through `app/board.py`.

**Tech Stack:** Python 3.11, uv, typer, NumPy/pandas, OpenCV + MediaPipe Tasks (`vision` extra, lazy imports), bleak (`device` extra), pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-11-02-live-demo-design.md` (read it first; §4.3 "Arms" and §4.6 are the contract). Reference only, never imported: `docs/superpowers/specs/2026-11-02-live-demo-spike-reference.py.txt`.

## Global Constraints

- `formcoach demo --source replay --headless` output (events, summary) and the shared `src/formcoach/rules/rules.yaml` stay byte-for-byte unchanged. `main` is never left red.
- `cv2` and `mediapipe` are imported lazily inside functions (optional `vision` extra); `bleak`/`pyserial` likewise (`device` extra). CI has neither extra nor the pose model: every new test runs without them or uses `pytest.importorskip("cv2")` / skips when `models/pose_landmarker_lite.task` is missing.
- `formcoach.signal` never imports `formcoach.pose`.
- No firmware or BLE protocol change. LEDs use `Command.LED_GOOD_REP = 0x01` and `Command.LED_FAULT = 0x02`.
- The demo never writes camera frames or video to disk. Only `events.parquet`, `frames.parquet`, `session.json`.
- OpenCV `putText` is ASCII-only: write `deg`, `|`, `-`; never `°`, `·`, `✓`, `⚠`.
- One command, no `--side` flag, no separate commands per arm. Arms are "l"/"r" in the person's own left/right; squat has `arm = None`.
- Per-arm visibility floor 0.5 on shoulder, elbow and wrist; bridge gaps of <= 3 frames (`MAX_GAP_FRAMES`).
- Board counts as alive only if a sample arrived within 2 s; gate with a board = gate flag AND alive.
- Banner shows ~3 s; paused video is dimmed to ~35%; black-camera hint when the mean of each of the first 30 frames is < 2.
- Rule thresholds are never tuned in the shared `rules.yaml`; any live tuning goes in a new per-pose-source file (ADR-0022).
- Good rep = no fault of any severity; flagged = >= 1 fault. Logging is on by default to `runs/live/<YYYYMMDD-HHMMSS>/`; `--out DIR` moves it; `--no-log` turns it off.
- Public APIs get docstrings with units. `pathlib` for paths. Ruff line length 100. Conventional commits.
- Commit locally per task on `feat/vision-first-run`. Do not push or open PRs without Christian's say-so. Never commit `SESSION-SUMMARY.md`, `.claude/`, `.serena/`, `firmware/.claude/`, `reports/.claude/`.

## Review Focus

1. Ctrl-C, `q`, closing the window, or the camera dying mid-run: the totals still print and the session log is still written (Task 8).
2. Person leaves the frame, or an arm is hidden for a while: HUD shows `--` (never `nan`), no crash, counting resumes (Tasks 4, 6, 8).
3. One arm curling or one arm idle: the idle arm stays at 0, and `CURL_ASYMMETRY` never fires on a one-arm curl (Task 4).
4. Session with zero reps: `session.json` has zeroed `arms`, parquet files are still written, exit code 0 (Task 8).
5. Board never found, silent, or `send` failing: webcam coaching keeps running, pill text says why, no exception reaches the loop (Tasks 5, 8).

### Task 3: Stateful `Pipeline` with replay identical

**Files:** Modify `src/formcoach/app/pipeline.py`; Create `tests/synthetic_pose.py`; Test `tests/test_pipeline_equivalence.py` (add).

- Produces in `pipeline.py`:
  ```python
  class Pipeline:
      def __init__(self, *, exercise: str, gate: GateBase | None = None, gate_name: str = "always_on",
                   rules=None, log: EventLog | None = None, on_event: Callable[[Event], None] | None = None,
                   side: str = "both", rep_config: dict | None = None, view: str = "frontal",
                   per_arm: bool = False, max_buffer_frames: int | None = None): ...
      gate_open: bool                      # property: current gate state
      buffered_frames: int                 # property: longest per-track angle buffer
      def on_imu(self, s: SISample, t: float | None = None) -> bool   # gate.update(s) -> set_gate(state, t or s.t); stores s.t/accel for the cross-check
      def set_gate(self, open_: bool, t: float) -> None               # emits gate_open/gate_close, resets tracks on close
      def on_frame(self, fr: PoseFrame) -> list[RepMetrics]           # logs the frame; processes it only if the gate is open; returns reps completed by this frame

      def finish(self, *, end_t: float | None = None, compute_imu: bool = True) -> PipelineResult
  ```
  `run_pipeline(...)` keeps its exact signature and becomes: build `Pipeline`, `for s in imu.iter_samples(): pipe.on_imu(s); while pending.t <= s.t: pipe.on_frame(pending)`, then `imu.close()`, trailing frames via `skip_frame`, `return pipe.finish()`.

### Task 4: Per-arm tracking

**Files:** Modify `src/formcoach/app/pipeline.py`; Test `tests/test_per_arm.py`.

**Interfaces:**
- Consumes: `Pipeline`, `_Track` (Task 3), `compute_rep_metrics(..., side=)`, `RepSegmenter.rep_start_t`, `tests/synthetic_pose.py`.
- Produces: `Pipeline(per_arm=True)`. For `curl|press|raise` it builds two tracks (`side="l", arm="l"` and `side="r", arm="r"`); for `squat` one track (`side="both", arm=None`). `RepMetrics` gains `arm: str | None = None`. With `per_arm=True`: `rep` event payloads and `fault` events carry `arm` ("l"/"r"/None) and `rep_id` counts per track; with `per_arm=False` payloads are unchanged. Constants `MIN_ARM_VISIBILITY = 0.5`, `TWO_ARM_OVERLAP = 0.5`.
- Produces `Pipeline.arm_totals() -> dict[str, dict]` keyed `"l"`, `"r"` (or `"all"` for squat): `{"reps": int, "good": int, "flagged": int, "faults_by_code": {code: n}}`; `finish()` adds it as `summary["arms"]` when `per_arm=True`.

Algorithm the tests do not determine:
- A track sees a frame only if the frame is valid and `min(visibility[shoulder_x, elbow_x, wrist_x]) >= MIN_ARM_VISIBILITY` (`fr.skeleton.index`); otherwise that track takes its own bridge/NaN path (gap counters per track).
- Primary angle per track: `primary_angle(exercise, a, track.side)`.
- Rules context per rep: `{"frontal_view"}` if `view == "frontal"`; plus `"two_arm"` for arm tracks only if the other arm is paired, and (unchanged from today) for `arm=None` tracks if `side == "both"`. Paired = the other track's last completed rep overlaps this rep by >= `TWO_ARM_OVERLAP` x the shorter duration, or the other track's `seg.rep_start_t` is not None and `rep.t_end - max(rep.t_start, start) >= 0.5 * min(rep.duration_s, rep.t_end - start)`.
- `max_buffer_frames`: when a track's buffers exceed `2 * max_buffer_frames`, drop the oldest down to `max_buffer_frames`, keep an `offset`, and shift `rep.i_start/i_end` by it (clamp at 0) before `compute_rep_metrics`.
- good = rep with no faults; flagged otherwise.

### Task 5: Wearable link (BLE find rounds, `BoardLink`)

**Files:** Modify `src/formcoach/io/ble.py`; Create `src/formcoach/app/board.py`; Test `tests/test_ble_find.py`, `tests/test_board.py`.

**Interfaces:**
- Produces `BLESource.scan_round_s: float = 2.0` and `async BLESource._find()`: loops `bleak.BleakScanner.find_device_by_filter(lambda d, adv: bool(d.name and d.name.startswith(self.name_prefix)), timeout=self.scan_round_s)` until a device is found or `_stop` is set; sets `device_name`; returns the `BLEDevice` (so `BleakClient` skips its own scan); returns `self.address` untouched when given. - Produces `app/board.py`:
  ```python
  SILENCE_S = 2.0
  class BoardLink:
      def __init__(self, source, *, silence_s: float = SILENCE_S, clock: Callable[[], float] = time.monotonic): ...
      name: str                                  # getattr(source, "device_name", None) or "board"
      def poll(self) -> list[SISample]           # non-blocking drain of the pump queue
      def alive(self) -> bool                    # a sample arrived within silence_s of clock()
      heard: bool                                # any sample ever
      def gate_open(self) -> bool                # alive() and the last sample's GATE_STATE flag
      def state(self) -> str                     # "waiting" (never heard) | "ok" | "silent" (heard, then > silence_s quiet)
      def send(self, cmd: protocol.Command) -> None   # forwards if the source has send(); never raises
      def close(self) -> None
  ```
  A daemon thread pumps `source.iter_samples()` into a queue as `(sample, arrival)` with `arrival = sample.t_arrival or clock()`.

**Interfaces:**

