# FormCoach Bench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `formcoach bench`: a UI-neutral live session in the core, a local web server, a lab console and a coach page, live tuning, and capture of replay-ready takes.

**Architecture:** `LiveSession` (`formcoach.app.session`) owns the live loop and publishes snapshots, IMU batches and events; it imports no UI. `formcoach.bench` is a separate package (Starlette + one WebSocket + static ES-module pages) that subscribes to a session. `run_live` / `demo --camera` become a second client of the same session.

**Tech Stack:** Python 3.11, NumPy, pandas/pyarrow, Starlette, uvicorn, websockets (all already in `uv.lock`), OpenCV + MediaPipe (existing `vision` extra), bleak/pyserial (existing `device` extra), plain ES modules, uPlot (vendored in `web/ble-viewer/vendor/`), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-18-bench-ui-design.md` (mockup: `2026-11-18-bench-ui-mockup.html` beside it). Read both before any task.

**Scope of this plan:** spec build steps 0–5. Step 6 (timeline review, `/review`) is a separate plan, written after the first two pages run on real hardware (Robert, 2026-11-18). One item of spec §7 is also left for that plan: the per-take opt-in that saves `video.mp4`. Nothing in this plan writes video.

## Global Constraints

- `formcoach demo --source replay --headless` output and `tests/golden/replay_mmfit_w00_curls.json` do not change. Every existing test passes **without being edited**, unless a task says otherwise.
- `formcoach.app.*`, `formcoach.io.*`, `formcoach.pose.*`, `formcoach.signal.*` never import `formcoach.bench`, `starlette`, `uvicorn` or `websockets`. `formcoach.signal` never imports `formcoach.pose`.
- Optional packages import lazily with an install hint: `uv sync --extra bench` (Starlette/uvicorn/websockets), `--extra vision`, `--extra device`.
- No pose, rep or rule logic in JavaScript. No Node build step. No text drawn over video. Colour is always paired with a word or icon.
- The server binds `127.0.0.1` only. No video is written unless a take opts in. Nothing under `data/team/` or `runs/` is ever committed.
- No firmware or BLE protocol change.
- Paths via `pathlib`; every command runs on Linux, macOS and Windows. Never `cd` in a shell command in this repo (a hook breaks); use repo-relative paths.
- Public functions get docstrings with units. Parquet schemas add columns, never rename.
- Gate source names, everywhere (code, messages, `meta.json`): `device`, `energy`, `always_on`, `manual`.
- Counter keys, everywhere: `"l"`, `"r"` (arm exercises) or `"all"` (squat).
- Commits: conventional (`feat:`, `fix:`, `test:`, `docs:`), one or more per task, ending with
  `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Write commit messages to a file and use `git commit -F` (backticks in `-m` get executed).
- Verify with `make lint test` (ruff check, ruff format --check, pytest, node tests) before each commit.

## Review Focus

1. **A browser tab that is slow, closed or opened twice** (lab + coach at once): the session loop must not slow down or stop; a new tab gets the current state at once. Test in Task 8.
2. **The watch drops out mid-run or mid-capture:** the session keeps running, the link state becomes `silent`, the gate (sources `device`/`energy`) closes, and a capture can still be kept with the IMU gap recorded. Tests in Tasks 2 and 6.
3. **No watch at all:** every feature except the IMU charts works; a take kept with zero IMU samples still writes a readable folder that replays. Tests in Tasks 6 and 7.
4. **No person in frame, or the frame source ends** (video file finished, camera unplugged): snapshots carry no landmarks, nothing crashes, and when frames end the server stays up and pages show "source ended". Tests in Tasks 1 and 8.
5. **A stale or malformed command** (unknown key, out-of-range value, capture command in the wrong state): answered with an `error` message, never an exception in the session thread. Tests in Tasks 5 and 8.

```python
# src/formcoach/app/session.py
GATE_SOURCES = ("device", "energy", "always_on", "manual")

@dataclass(slots=True)
class Snapshot:
    index: int                      # frame index from the source
    t: float                        # s on the frame source's clock
    t_mono: float                   # s, session clock() when step() received the frame
    frame: np.ndarray | None        # raw BGR, unmirrored
    image_landmarks: np.ndarray | None   # (33, 4) x, y, z, visibility; None if pose did not run or found nobody
    world_landmarks: np.ndarray | None   # (33, 3) metres
    pose_ran: bool
    gate: bool                      # the gate the pipeline used for this frame
    gate_source: str                # one of GATE_SOURCES
    gates: dict[str, bool | None]   # {"device": ..., "energy": ...}; None when no board
    energy: float | None            # latest var(|a|) window value, (m/s^2)^2
    angles: dict[str, float]        # every tracked joint angle of this frame, degrees ({} if none)
    counters: dict[str, dict]       # key -> {"angle": float|None, "enter": float, "exit": float, "armed": bool, "visibility": float|None}
    totals: dict[str, dict]         # Pipeline.arm_totals()
    completed: list[RepMetrics]     # reps finished on this frame
    fps: float
    exercise: str
    link_state: str                 # "none" | "waiting" | "ok" | "silent"

class LiveSession:
    def __init__(self, *, exercise: str, detect: DetectFn, rules=None, board=None,
                 clock: Callable[[], float] = time.monotonic, rep_config: dict | None = None,
                 gate_source: str | None = None, report_dropped: bool = True,
                 on_event: Callable[[Event], None] | None = None): ...
    log: EventLog                   # one log for the whole session
    pipeline: Pipeline
    exercise: str
    gate_source: str                # default: "device" if board else "always_on"
    def subscribe(self, *, on_snapshot=None, on_imu=None, on_event=None) -> Callable[[], None]: ...
    def call(self, fn: Callable[["LiveSession"], None]) -> None: ...   # thread-safe; runs at the start of the next step()
    def step(self, index: int, t: float, frame: np.ndarray | None) -> Snapshot: ...
    def run(self, frames: Iterable[tuple[int, float, np.ndarray]]) -> None: ...  # until frames end or stop()
    def stop(self) -> None: ...     # thread-safe
    def finish(self) -> PipelineResult: ...   # pipe.finish(compute_imu=False) plus live/board/fps_mean/duration_s
    def emit(self, kind: str, t: float | None = None, **payload) -> Event: ...  # session-level event: logged + sent to listeners
```

Rules of behaviour (the tests pin them):
- `step` order: drain `call` queue → `board.poll()` and hand the polled samples to `on_imu` listeners and to the shadow `EnergyGate` → choose the gate from `gate_source` → `pipe.set_gate` → detect and `pipe.on_frame` when the gate is open, else `pipe.skip_frame` → LED command → build and publish the `Snapshot`.
- Gate by source: `device` = `board.gate_open()`; `energy` = shadow gate state **and** `board.alive()`; `always_on` = True; `manual` = the value set by `set_manual_gate` (Task 2). `device`/`energy` with no board give False.
- The LED rule moves here unchanged from `run_live` (one command per frame, `LED_FAULT` wins, `LED_GOOD_REP` held back `FAULT_FLASH_S` after a fault; send errors ignored).
- Listener callbacks run on the session thread. An exception raised by a listener is caught, emitted once as an `error` event, and never stops the loop.
- `EnergyGate.last_value: float | None` is set in `decide`.

**Clock fit algorithm** (the tests do not determine it): `delta = t_arrival - t_device`. Batching and radio latency only ever add to `delta`, so the true mapping is its lower envelope. Split the samples into 1 s bins of `t_device`; take the minimum `delta` per bin; least-squares fit `delta_min = drift * t_device + offset_s` over the bins (`method="envelope"`); `residual_ms` = median absolute deviation of the bin minima from the line. With fewer than 3 bins: `drift = 0`, `offset_s = min(delta)`, `method="offset"`. With no samples: zeros, `method="none"`.

**Folder contents** (`t` in every file is seconds since the take's `t0_mono`):
- `imu.parquet`: `schema.make_imu_stream(dataset="team", device="formcoach", placement="wrist_l", ...)` with `t = to_laptop(fit, t_device) - t0`, plus columns `flags`, `seq`, `t_arrival`, `t_device`. Zero rows is valid.
- `pose.parquet`: `pose.store.write_pose(..., skeleton="mediapipe33", image=..., valid=...)`, one row per frame, world landmarks stored at full precision the writer allows.
- `events.parquet`, `frames.parquet`: same columns as `EventLog.write` (frames carry `t, processed, gate_state` and the per-counter diagnostics).
- `meta.json`: the `SessionRecorder` keys, plus `"bench": {"version": 1}`, `labels`, `arm`, `expected_reps` (= `true_reps`, per arm), `clock` (the `ClockFit` fields), `overrides`, `gate_source`, `rules`, `model`, `camera`, `firmware`, `device`, `kit`, `summary`.
- One line appended to `<root>/<subject>/sets.csv` with header `session_id,exercise,form,reps,notes,arm`; an existing five-column file gets the `arm` column added (existing rows: empty).

**Session behaviour:**
- `start_capture`: refuses unless `idle` (RuntimeError); resets counters; `countdown` for `delay_s`, then `recording`. Labels' exercise must equal the session's (else ValueError).
- While `recording`: pose runs on **every** frame; when the gate is closed the frame is recorded with its landmarks but the pipeline gets `skip_frame`. Every snapshot, IMU batch and event goes into the take.
- `auto_stop=True`: after the gate has been open at least once, 5.0 s of closed gate moves to `review`. Ignored when `gate_source == "always_on"`.
- Each state change emits a `capture` event `{state, ...}`; `review` carries the summary.
- `note_cue_shown`: latency = `t_mono` − the `t_mono` of the frame that completed that rep; emitted as `cue_shown` `{arm, rep_id, latency_ms}` and stored in the take.
