# FormCoach

Sensor-gated webcam form coaching. A wrist wearable the team builds (Seeed XIAO ESP32-S3 +
BMI160 IMU) runs a tiny int8 neural network that says "exercise in progress" over Bluetooth. A
Python app on a laptop uses that as a *gate*: only while the gate is open does it run MediaPipe
pose estimation on the webcam, segment reps and apply biomechanical rules to flag form faults on
four dumbbell exercises (bicep curl, overhead press, lateral raise, squat).

**Claim under test:** gated vision gives the same per-rep feedback as always-on vision while
processing a fraction of the frames on an ordinary laptop CPU.

BDA 696 group project, SDSU, Fall 2026. Team: Robert Ashe (lead), Ruby Rios Ramirez,
Rochelle Reyes, Christian Byars, Bryce Hall.

## Quickstart (5 minutes, no hardware needed)

Prerequisites: [git](https://git-scm.com/) and [uv](https://docs.astral.sh/uv/getting-started/installation/).
`uv` downloads the right Python (3.11) for you; you do not need Python installed.

### Linux / macOS

```bash
git clone https://github.com/nthPerson/BDA696_Group_Project.git formcoach
cd formcoach
make setup     # creates .venv, installs the package + dev tools, installs git hooks
make demo      # runs the replay pipeline on public data (no wearable, no webcam)
```

### Windows

Use **Git Bash** (comes with Git for Windows) or PowerShell. `make` is not installed by default
on Windows; either install it once (`winget install ezwinports.make`) and use the commands above
in Git Bash, or run the equivalent `uv` commands directly:

```powershell
git clone https://github.com/nthPerson/BDA696_Group_Project.git formcoach
cd formcoach
uv sync --group dev              # = make setup
uv run pre-commit install
uv run formcoach demo --source replay   # = make demo
```

Serial ports on Windows are `COM3`, `COM5`, ... (Device Manager → Ports). On Linux they are
`/dev/ttyACM0` (add yourself to the `dialout` group), on macOS `/dev/cu.usbmodem*`.

## Everyday commands

| `make` target | Direct equivalent | What it does |
|---|---|---|
| `make setup` | `uv sync --group dev` | install everything needed for the replay pipeline |
| `make setup-all` | `uv sync --all-extras --group dev` | + MediaPipe/OpenCV, BLE/serial, TensorFlow/PyTorch, Streamlit |
| `make lint` / `make format` | `uv run ruff check .` / `uv run ruff format .` | lint and format (CI runs lint) |
| `make test` | `uv run pytest` | unit + integration tests |
| `make data DATASET=mmfit` | `uv run formcoach data fetch --dataset mmfit` | download + verify a dataset (resumable) |
| `make convert` | `uv run formcoach data convert` | raw downloads → IMUStream Parquet under `data/processed/` |
| `make profile` | `uv run formcoach data profile` | write `reports/data_profile.md` |
| `make features` | `uv run formcoach features build` | windows + features → `data/processed/` |
| `make train-gate` | `uv run formcoach train gate` | train the gate model, export int8 |
| `make eval` | `uv run formcoach eval all` | regenerate every table/figure in `reports/` |
| `make demo` | `uv run formcoach demo --source replay` | the demo of record (add `SOURCE=ble` with hardware) |
| `make record PORT=COM5` | `uv run formcoach record --source serial --port COM5` | record a team session |
| `make fw-build` | `uvx platformio run -d firmware` | compile the wearable firmware |

`uv run formcoach --help` lists every command. Optional extras install with
`uv sync --extra vision` (webcam + pose), `--extra device` (BLE/serial), `--extra train`
(Keras/PyTorch, CPU wheels), `--extra app` (dashboard).

## Working agreements

- One task → one branch → one pull request with a description a teammate can follow.
  Conventional commit prefixes: `feat:`, `fix:`, `data:`, `docs:`, `fw:`, `chore:`, `test:`.
- `make lint test` must pass before merge; `main` is never broken. Pre-commit hooks enforce
  formatting locally and block direct commits to `main`.
- Raw datasets and team recordings are **never committed**. `data/MANIFEST.md` records every
  file's source, SHA-256 and license. No video of a teammate is ever pushed anywhere.
- After a work session, add an entry to `docs/STATUS.md`; when you choose between alternatives,
  add a paragraph to `docs/DECISIONS.md`.
- Hardware: read the **battery safety** section of `docs/03-hardware.md` before touching a
  LiPo cell. Protected cells only, charge attended, never bypass the protection circuit.
