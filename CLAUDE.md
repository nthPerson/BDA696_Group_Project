# FormCoach — persistent directives for Claude Code (and humans)

You are the lead engineer on **FormCoach**, the BDA 696 (SDSU, Fall 2026) group project: a
team-built wrist wearable (Seeed XIAO ESP32-S3 + BMI160) that detects "exercise repetition in
progress" and wakes a webcam pose-estimation pipeline on a laptop, which applies biomechanical
rules to give per-rep form feedback. Everything must be **complete, evaluated, documented and
presented by December 9, 2026**. Scope is frozen to four dumbbell exercises (curl, press,
lateral raise, squat) with rule-based feedback.

## Non-negotiable working rules

1. **Public data first; hardware never blocks software.** Every model, pipeline stage and
   evaluation runs on public datasets and recorded sessions with `--source replay`. Live
   hardware paths are additive. `formcoach demo --source replay --headless` must always work.
2. **Small, reviewable increments.** One task → one branch → one PR. Conventional commits
   (`feat:`, `fix:`, `data:`, `docs:`, `fw:`, `test:`, `chore:`). Never leave `main` broken.
3. **Reproducibility.** `uv` with the committed `uv.lock` (`uv sync --locked` in CI),
   `firmware/platformio.ini`, and a `Makefile` target for every workflow (`setup lint test data
   features train-gate eval demo record fw-build`). Seeds fixed and logged. Results tables are
   regenerated by scripts under `reports/`, never hand-edited.
4. **Data hygiene.** Raw data under `data/external/`, processed under `data/processed/`, team
   recordings under `data/team/` — all gitignored. `data/MANIFEST.md` records every file with
   URL, SHA-256, size, license, date. Team subjects are `S1`–`S5`; **no video of a teammate is
   ever pushed anywhere**. Only small fixtures under `data/fixtures/` are committed.
5. **Tests and lint pass before merge.** `pytest` (unit tests for loaders, windowing, angle
   math, rules, rep segmentation; one integration test running the replay pipeline on a
   30-second fixture), `ruff` check + format, and `pio run` for firmware, all in CI on push/PR.
6. **Keep `docs/STATUS.md` current** after every session (what changed, next, open questions,
   blockers). Add an ADR paragraph to `docs/DECISIONS.md` whenever you choose between
   alternatives or a **(verify)** item turns out different from the docs.
7. **Ask Robert before**: ordering parts; changing the pin map after boards are built;
   deleting data; changing the BLE protocol after firmware is deployed to teammates' devices;
   expanding scope beyond frozen v1; building the PocketTrainer fallback (§9 of the design doc)
   before the ~Nov 3 go/no-go. Otherwise proceed autonomously and report.
8. **Evaluation is a first-class deliverable.** Metrics scripts exist by the end of Phase 1
   and run on every new model or data drop. Headline numbers are leave-one-subject-out on
   unseen subjects; never report seen-subject accuracy as the headline.
9. **Safety.** The LiPo rules in `docs/03-hardware.md` §4 go verbatim into every hardware doc
   you write. Never instruct anyone to charge an unattended cell or bypass the protection circuit.
10. **Scope discipline.** Stretch goals (`docs/05-roadmap.md` §4) are off-limits until feature
    freeze (~Nov 10). Keep `formcoach.signal` free of any import from `formcoach.pose` so the
    IMU-only fallback stays buildable.

## Conventions that keep the team unblocked

- Every CLI command and Makefile target must run on Linux, macOS and Windows. Paths via
  `pathlib`; no shell-specific tricks in Python; serial ports are `/dev/ttyACM0`,
  `/dev/cu.usbmodem*`, `COMx`.
- Public APIs get docstrings with units (m/s², rad/s, degrees, seconds). Parquet schemas
  follow `docs/02-system-design.md` §5 exactly; add columns, never rename.
- Reports under `reports/` are Markdown tables + PNG written by `formcoach eval …`; the report
  and slides cite those files.
- Firmware: `include/protocol.h` and `src/formcoach/io/protocol.py` change together with
  `tests/test_protocol.py`; constants for hysteresis and scaling live in `protocol.h` /
  `model/preprocess.json` and in `rules.yaml` for the laptop-side gate.
- Prefer boring, well-known libraries; no message brokers, no cloud dependencies in the core
  path, no paid APIs.
- Robert's clone may live on a OneDrive/9p mount under WSL; if `uv` complains about hardlinks
  set `UV_LINK_MODE=copy`, and never assume the working tree is fast.
